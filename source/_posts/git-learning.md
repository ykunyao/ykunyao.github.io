## 1. Git 基础概念

### 1.1 什么是 Git？

```
Git 是一个"版本控制系统"（Version Control System）

类比理解：
┌─────────────────────────────────────────────────────────────┐
│  想象你在写小说，Git 就是你的"时光机"                          │
├─────────────────────────────────────────────────────────────┤
│  Chapter1.txt  ──▶ 写完了，保存一个"快照"叫"第一章完成"          │
│  Chapter2.txt  ──▶ 写完了，保存一个"快照"叫"第二章完成"          │
│  Chapter3.txt  ──▶ 写坏了，想回到"第一章完成"？一个命令搞定！     │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 Git 的三种状态

```
Git 文件的"人生"三个阶段：

         ┌─────────────────────────────────────────────────┐
         │                   核心概念                         │
         ├─────────────────────────────────────────────────┤
         │                                                  │
         │  1️⃣ Modified (已修改)                              │
         │     📝 你修改了文件，但还没告诉 Git                  │
         │     状态：文件被改动，但未暂存                        │
         │                                                  │
         │          ▼ git add                               │
         │          ▼                                       │
         │                                                  │
         │  2️⃣ Staged (已暂存)                                │
         │     📦 你告诉 Git："这个改动我要保存"                │
         │     状态：改动已加入暂存区，等待提交                  │
         │                                                  │
         │          ▼ git commit                             │
         │          ▼                                       │
         │                                                  │
         │  3️⃣ Committed (已提交)                             │
         │     ✅ Git 正式记录了这个版本                       │
         │     状态：改动已安全保存在本地仓库                   │
         │                                                  │
         └─────────────────────────────────────────────────┘
```

### 1.3 记忆口诀

```
┌─────────────────────────────────────────────────────────────┐
│  🎯 Git 状态记忆口诀                                        │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  "工作区是厨房，暂存区是餐盘，仓库是保险箱"                     │
│                                                              │
│  📝 工作区 (Working Directory)  =  厨房      → 你在做饭        │
│  📦 暂存区 (Staging Area)      =  餐盘      → 准备上菜        │
│  ✅ 仓库   (Repository)        =  保险箱    → 正式存档        │
│                                                              │
│  工作流程：做饭(修改) → 装盘(暂存) → 存档(提交)                │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## 2. 首次配置（必做）

> ⚠️ 每次换电脑/重装系统后都要做！

### 2.1 为什么要配置？

```
Git 需要知道"你是谁"，因为：
- 每次提交都会记录作者信息
- 这是你的"签名"，证明代码是谁写的
```

### 2.2 配置命令详解

```bash
# ============================================================
# 设置你的用户名（提交时会显示这个名字）
# ============================================================
git config --global user.name "你的名字"

# ============================================================
# 设置你的邮箱（建议用 GitHub 注册邮箱）
# ============================================================
git config --global user.email "your.email@example.com"

# ============================================================
# 设置默认编辑器（VS Code）
# 如果不设置，Git 会用默认编辑器（可能是 vi，很丑）
# ============================================================
git config --global core.editor "code --wait"

# ============================================================
# 设置命令别名（让常用命令变短）
# ============================================================
git config --global alias.st "status"       # git st 替代 git status
git config --global alias.co "checkout"      # git co 替代 git checkout
git config --global alias.br "branch"       # git br 替代 git branch
git config --global alias.lg "log --graph --oneline --all"  # 可视化日志
```

### 2.3 验证配置

```bash
# 查看所有配置
git config --list

# 查看某个配置
git config user.name
git config user.email
```

## 3. 创建仓库 & 基本操作

### 3.1 创建仓库的两种方式

```bash
# ============================================================
# 方式一：从零开始创建（本地已有项目）
# ============================================================
mkdir my-project          # 创建项目文件夹
cd my-project             # 进入文件夹
git init                  # 初始化 Git 仓库

# 执行 git init 后会发生什么？
# 1. 创建 .git 文件夹（隐藏的）
# 2. Git 开始跟踪这个文件夹的所有变化
# 3. 此时文件夹还是"空"的，没有任何提交

# ============================================================
# 方式二：克隆远程仓库（已有项目在 GitHub/GitLab）
# ============================================================
git clone https://github.com/user/repo.git

# 克隆后会：
# 1. 下载整个项目到本地
# 2. 自动创建同名文件夹
# 3. 自动配置好远程仓库信息
```

### 3.2 基本操作命令

#### git status - 查看状态

```bash
# 最最常用的命令！
# 显示工作区、暂存区的状态
git status

# 简化输出（推荐）
git status -s
# 输出示例：
#  M file.txt        (M = 已修改，在暂存区)
#  MM old.txt        (MM = 修改后又放回工作区)
# ?? new.txt        (?? = 未跟踪的新文件)

# ============================================================
# 状态含义详解：
# ============================================================
# ?? = Untracked（未跟踪）
#     → 新文件，Git 还不认识它
#
#  A = Added（已添加）
#     → 新文件已添加到暂存区
#
#  M = Modified（已修改）
#     → 文件被修改了
#     M 出现在左边 = 暂存区有改动
#     M 出现在右边 = 工作区有改动
#
#  D = Deleted（已删除）
#     → 文件被删除了
#
#  R = Renamed（已重命名）
#     → 文件被移动或重命名了
```

#### git add - 添加到暂存区

```bash
# ============================================================
# 添加单个文件（最常用）
# ============================================================
git add filename.txt

# ============================================================
# 添加所有修改（最最常用！）
# ============================================================
git add .

# ⚠️ 注意：git add . 会添加所有改动，包括删除的文件
# 小心误操作！

# ============================================================
# 添加所有已跟踪文件的修改（不包括新文件）
# ============================================================
git add -u

# ============================================================
# 添加所有 .txt 文件
# ============================================================
git add *.txt

# ============================================================
# 交互式添加（可视化选择）
# ============================================================
git add -i
# 会显示菜单让你选择要添加的内容

# ============================================================
# 记忆技巧：git add 的"A"像不像一个钩子？
# ============================================================
#     把文件"钩"到暂存区
#     "add" = "加到暂存区"
```

#### git commit - 提交到仓库

```bash
# ============================================================
# 基本提交（会弹出编辑器写提交信息）
# ============================================================
git commit

# ============================================================
# 提交并附带信息（最常用！）
# ============================================================
git commit -m "这里写提交信息"

# ============================================================
# 提交信息规范（推荐格式）
# ============================================================
git commit -m "feat: 添加用户登录功能"
git commit -m "fix: 修复登录页面样式错位"
git commit -m "docs: 更新 README 文档"
git commit -m "refactor: 重构用户模块代码"

# ============================================================
# 提交信息格式说明：
# ============================================================
# feat:     新功能
# fix:      修复 bug
# docs:     文档更新
# style:    格式调整（不影响代码）
# refactor: 重构（不是修复也不是新功能）
# perf:     性能优化
# test:     测试相关
# chore:    杂项（构建、依赖更新等）

# ============================================================
# 将已暂存的文件提交（快捷方式）
# ============================================================
git commit -m "message"

# ============================================================
# 跳过暂存区直接提交（⚠️ 危险操作！）
# ============================================================
git commit -am "message"
# 注意：-a 只会提交已跟踪文件的修改，不会添加新文件

# ============================================================
# 修改最后一次提交（补救用）
# ============================================================
# 如果提交信息写错了：
git commit -m "fie 修复bug"    # 写错了！
git commit --amend              # 修改上一次的提交信息

# 如果忘了添加某个文件：
git add forgotten-file.txt
git commit --amend              # 把忘记的文件"补"进去

# ============================================================
# 记忆技巧：commit = "提交/承诺"
# ============================================================
# 就像把东西正式放进保险箱，要郑重其事
# commit 信息就是"保险箱的标签"
```

#### git diff - 查看差异

```bash
# ============================================================
# 查看工作区 vs 暂存区的差异
# ============================================================
git diff

# ============================================================
# 查看暂存区 vs 仓库的差异（看看提交了什么）
# ============================================================
git diff --staged
git diff --cached    # 同上，简写形式

# ============================================================
# 查看工作区 vs 仓库最新提交的差异
# ============================================================
git diff HEAD

# ============================================================
# 查看两个提交之间的差异
# ============================================================
git diff commit1 commit2
git diff HEAD~3 HEAD    # 当前版本 vs 3个版本前

# ============================================================
# 只看某个文件的差异
# ============================================================
git diff filename.txt

# ============================================================
# 简洁模式（只显示文件名，不显示具体内容）
# ============================================================
git diff --stat
# 输出示例：
#  file1.txt | 5 ++---
#  file2.py  | 10 ++++++
#  2 files changed, 8 insertions(+), 3 deletions(-)
```

### 3.3 完整示例：你的第一个提交

```bash
# 1. 创建项目并进入
mkdir my-first-repo
cd my-first-repo

# 2. 初始化 Git 仓库
git init

# 3. 创建一个文件
echo "Hello Git!" > hello.txt

# 4. 查看状态（此时文件是 Untracked）
git status
# 输出：
# Untracked files:
#   (use "git add <file>..." to include in what will be committed)
#     hello.txt

# 5. 添加到暂存区
git add hello.txt

# 6. 再次查看状态（文件变成 Staged）
git status
# 输出：
# Changes to be committed:
#   (use "git restore --staged <file>..." to unstage)
#     new file:   hello.txt

# 7. 提交到仓库
git commit -m "feat: 创建首个文件，输出 Hello Git!"

# 8. 查看提交历史
git log
# 输出：
# commit xxxxxxx (HEAD -> master)
# Author: Your Name <your@email.com>
# Date:   Sat Apr 11 00:00:00 2026
#
#     feat: 创建首个文件，输出 Hello Git!
```

## 4. 时光机：查看与回退

### 4.1 查看历史

```bash
# ============================================================
# 查看完整提交历史（详细版）
# ============================================================
git log

# 输出示例：
# commit a1b2c3d4e5f6
# Author: 张三 <zhangsan@example.com>
# Date:   2026-04-11 10:30:00
#
#     feat: 添加用户模块
#
# commit e5f6a7b8c9d0
# Author: 张三 <zhangsan@example.com>
# Date:   2026-04-10 15:20:00
#
#     init: 项目初始化

# ============================================================
# 简洁版（单行显示）
# ============================================================
git log --oneline

# 输出示例：
# a1b2c3d feat: 添加用户模块
# e5f6a7b init: 项目初始化

# ============================================================
# 可视化图形版（推荐！）
# ============================================================
git log --graph --oneline --all

# 输出示例：
# * a1b2c3d feat: 添加用户模块
# * e5f6a7b init: 项目初始化

# ============================================================
# 查看最近 N 次提交
# ============================================================
git log -3          # 最近 3 次
git log --oneline -5 # 最近 5 次（简洁版）

# ============================================================
# 查看某个文件的修改历史
# ============================================================
git log filename.txt

# ============================================================
# 查看某个提交的具体内容
# ============================================================
git show commit-id

# ============================================================
# 查找某个人的提交
# ============================================================
git log --author="张三"
```

### 4.2 版本回退（核心技能！）

```bash
# ============================================================
# 先理解 HEAD 的概念
# ============================================================
# HEAD 是 Git 的"当前指针"，永远指向你当前所在的版本

# master/main 分支上，HEAD 通常指向最新提交
# 类似于游戏中的"当前存档点"

# ============================================================
# 方式一：git reset --soft（软回退）
# ============================================================
git reset --soft HEAD~1

# 效果：
# - 撤销最后一次提交
# - 但保留修改在暂存区
# - 工作区的改动不会丢失

# 适用场景：提交后发现少加了文件，想"补交"

# ============================================================
# 方式二：git reset --mixed（混合回退，默认）
# ============================================================
git reset HEAD~1
# 或
git reset --mixed HEAD~1

# 效果：
# - 撤销最后一次提交
# - 保留修改在工作区（不在暂存区）
# - 这是"回退到过去，但保留改动"的方式

# 适用场景：提交后发现提交信息写错了，想重新写

# ============================================================
# 方式三：git reset --hard（硬回退）
# ============================================================
git reset --hard HEAD~1

# 效果：
# - 撤销最后一次提交
# - 丢弃所有修改（危险！）
# - 彻底回到上一个版本

# ⚠️ 警告：这个操作会丢失数据，除非确实不想要那些改动了
# 适用场景：提交了一个完全错误的版本，想彻底丢弃

# ============================================================
# 回退到指定版本
# ============================================================
git reset --hard commit-id

# 先用 git log 找到目标版本的 commit-id
git log --oneline
# abc1234 feat: 添加功能C
# def5678 feat: 添加功能B
# ghi9012 init: 项目初始化

# 回退到项目初始化
git reset --hard ghi9012

# ============================================================
# 记忆技巧：三种回退方式的区别
# ============================================================
# soft   = 软：提交没了，改动还在暂存区（最温柔）
# mixed  = 混：提交没了，改动还在工作区（默认，最常用）
# hard   = 硬：提交没了，改动也没了（最彻底，最危险）
```

### 4.3 撤销修改

```bash
# ============================================================
# 撤销工作区的修改（还没 add）
# ============================================================
git checkout -- filename.txt
# 或（新语法）
git restore filename.txt

# 效果：将文件恢复到最近一次 commit 的状态
# ⚠️ 会丢失工作区的修改，谨慎使用！

# ============================================================
# 撤销暂存区的修改（已经 add 了）
# ============================================================
git reset HEAD filename.txt
# 或（新语法）
git restore --staged filename.txt

# 效果：将文件从暂存区放回工作区
# 不会丢失修改，只是"取消暂存"

# ============================================================
# 撤销单个文件到某个版本
# ============================================================
git checkout commit-id -- filename.txt
# 或（新语法）
git restore --source=commit-id filename.txt

# ============================================================
# 删除文件（并提交）
# ============================================================
git rm filename.txt

# 先删除文件，再提交
# 等于在工作区删 + 在仓库删

# ============================================================
# 只从 Git 删除，但不删除工作区文件
# ============================================================
git rm --cached filename.txt

# 适用场景：想把文件从 Git 移除，但保留在本地
```

## 5. 分支管理（核心技能）

### 5.1 分支概念

```
┌─────────────────────────────────────────────────────────────────┐
│  🎯 分支是什么？                                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  分支 = 时间的"平行宇宙"                                          │
│                                                                  │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │                     master/main                           │   │
│  │  ●────●────●────●                                        │   │
│  │  ↑                                                           │   │
│  │  HEAD（当前分支）                                             │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │                 feature/login（新建分支）                  │   │
│  │     ●────●                                                  │   │
│  │    /                                                         │   │
│  │ ●────●                                                       │   │
│  │ ↑                                                            │   │
│  │ 从这里分出去                                                  │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                  │
│  好处：可以同时开发多个功能，互不干扰！                            │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 分支基础命令

```bash
# ============================================================
# 查看所有分支
# ============================================================
git branch

# 输出：
#   feature/login    （* = 当前分支）
# * master
#   bugfix/header

# ============================================================
# 查看所有分支（包括远程）
# ============================================================
git branch -a

# ============================================================
# 创建新分支（但不切换）
# ============================================================
git branch feature-new

# ============================================================
# 切换分支（最常用！）
# ============================================================
git checkout feature-new
# 或（新语法）
git switch feature-new

# ============================================================
# 创建并切换到新分支（一步到位！）
# ============================================================
git checkout -b feature-new
# 或（新语法）
git switch -c feature-new

# ============================================================
# 删除分支
# ============================================================
git branch -d feature-old
# ⚠️ 如果分支有未合并的改动，需要用 -D 强制删除
git branch -D feature-old

# ============================================================
# 重命名分支
# ============================================================
git branch -m old-name new-name
```

### 5.3 合并分支

```bash
# ============================================================
# 合并分支（把其他分支合并到当前分支）
# ============================================================

# 场景：我在 feature 分支完成了开发，要合并到 master

# 1. 先切换到主分支
git checkout master

# 2. 把 feature 分支合并进来
git merge feature

# ============================================================
# 合并方式详解
# ============================================================

# 1. Fast-forward（快进合并）
#    适用：当 master 没有新的提交时
#    效果：只是把指针前移，非常快

#    之前：
#    master: ●────●
#    feature:       ●────●
#
#    合并后：
#    master: ●────●────●
#                  ↑    ↑
#               原来   现在

# 2. Three-way merge（三方合并）
#    适用：当 master 也有新提交时
#    效果：Git 会创建一个新的"合并提交"

#    之前：
#    master:     ●────●
#                   ↘
#                     ×  （合并提交）
#                   ↗
#    feature: ●────●
#
#    合并后：
#    master:     ●────●────×
#                       ↗ ↘
#    feature: ●────●───────

# ============================================================
# 解决合并冲突
# ============================================================
# 当两个分支修改了同一文件的同一部分时，会发生冲突

# Git 会提示：
# CONFLICT (content): Merge conflict in filename.txt
# Automatic merge failed; fix conflicts and then commit it.

# 冲突文件内容：
# <<<<<<< HEAD
# 当前分支的内容
# =======
# 要合并的分支的内容
# >>>>>>> feature

# 解决方法：
# 1. 手动编辑文件，保留要保留的内容
# 2. 删除 Git 添加的标记符号 <<<<<<< ======= >>>>>>>
# 3. git add filename.txt
# 4. git commit -m "fix: 解决合并冲突"
```

### 5.4 变基（Rebase）

```bash
# ============================================================
# 什么是变基？
# ============================================================
# 变基 = 把当前分支的"基础"改到另一个分支的末端
# 让提交历史变成一条直线

# 场景：你在 feature 分支开发，主分支 master 有更新

# 之前：
# master:     ●────●────●
#                  ↘
#    feature:     ●────●
#
# 你想让 feature 基于最新的 master：

# 1. 切换到 feature 分支
git checkout feature

# 2. 变基到 master
git rebase master

# 之后：
# master:     ●────●────●
#                       ↘
#    feature:            ●────●

# ============================================================
# ⚠️ 黄金法则：不要对已推送到远程的提交进行变基！
# ============================================================
# 变基会改变提交历史，如果别人已经基于这些提交工作，会造成混乱

# ============================================================
# 交互式变基（修改提交历史）
# ============================================================
git rebase -i HEAD~3

# 会打开编辑器，显示最近 3 个提交，可以：
# - pick：保留这个提交
# - reword：修改提交信息
# - squash：把这个提交合并到上一个
# - drop：删除这个提交

# 用途：整理提交历史，让提交历史更清晰
```

### 5.5 暂存工作

```bash
# ============================================================
# git stash - 临时保存工作进度
# ============================================================
# 场景：正在开发新功能，突然要修 bug，需要切换分支
# 但又不想提交半成品

# 1. 暂存当前改动
git stash
# 或
git stash save "正在开发登录功能"

# 2. 切换到其他分支处理 bug
git checkout master
# ... 修复 bug ...
git commit -m "fix: 修复了 XX bug"

# 3. 回到开发分支
git checkout feature

# 4. 恢复暂存的改动
git stash pop        # 恢复并删除暂存
# 或
git stash apply      # 恢复但保留暂存

# ============================================================
# 其他 stash 命令
# ============================================================
git stash list           # 查看所有暂存
git stash show           # 查看暂存的内容
git stash drop           # 删除一个暂存
git stash clear          # 清空所有暂存
```

### 5.6 分支实战流程

```bash
# ============================================================
# 标准的功能开发流程
# ============================================================

# 1. 从 master 创建功能分支
git checkout -b feature/user-login master

# 2. 在功能分支开发...
git add .
git commit -m "feat: 添加登录页面"

# 3. 继续开发...
git add .
git commit -m "feat: 实现登录验证"

# 4. 开发完成，变基到最新的 master（保持线性历史）
git fetch origin master
git rebase origin/master

# 5. 切换到 master 并合并
git checkout master

# 6. 删除功能分支

# 7. 推送代码

```

## 6. 远程仓库协作

### 6.1 远程仓库概念

```
┌─────────────────────────────────────────────────────────────────┐
│  GitHub / GitLab = 远程仓库（云端）                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│     本地仓库                      远程仓库                        │
│  ┌─────────────┐              ┌─────────────┐                  │
│  │  .git/      │ ── push ──▶  │  GitHub     │                  │
│  │  本地代码    │              │  云端代码    │                  │
│  └─────────────┘  ◀── pull ─── └─────────────┘                  │
│       │                                       │                  │
│       └────────── clone ──────────────────────▶│ 第一次获取       │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 6.2 远程仓库命令

```bash
# ============================================================
# 查看远程仓库
# ============================================================
git remote -v

# 输出：
# origin  https://github.com/user/repo.git (fetch)
# origin  https://github.com/user/repo.git (push)

# origin = 默认的远程仓库别名（可以改成其他名字）

# ============================================================
# 添加远程仓库
# ============================================================
git remote add origin https://github.com/user/repo.git

# ============================================================
# 重命名远程仓库
# ============================================================
git remote rename origin upstream

# ============================================================
# 推送代码到远程
# ============================================================
git push origin master
# 解释：
# - origin = 远程仓库别名
# - master = 要推送的分支名

# 第一次推送时设置上游分支
git push -u origin master
# -u = --set-upstream，以后可以直接 git push

# ============================================================
# 拉取代码
# ============================================================
git pull origin master
# 解释：拉取远程 master 并合并到当前分支

# 如果有冲突，需要解决冲突后再提交

# ============================================================
# 克隆仓库
# ============================================================
git clone https://github.com/user/repo.git
git clone https://github.com/user/repo.git my-folder  # 指定文件夹名

# ============================================================
# 获取远程更新（不合并）
# ============================================================
git fetch origin
# 获取远程的更新，但不合并到本地分支
# 类似于"看看远程有什么新变化"

# 查看远程分支
git branch -r

# ============================================================
# 推送所有标签
# ============================================================
git push origin --tags
```

### 6.3 标签管理

```bash
# ============================================================
# 什么是标签？
# ============================================================
# 标签 = 给某个提交起一个有意义的名字
# 常用于标记版本号：v1.0.0, v2.0.0

# ============================================================
# 创建标签
# ============================================================
# 给当前提交打标签
git tag v1.0.0

# 给历史提交打标签
git tag v0.9.0 commit-id

# 创建带说明的标签
git tag -a v1.0.0 -m "版本1.0.0发布"

# ============================================================
# 查看标签
# ============================================================
git tag           # 列出所有标签
git tag -l "v1.*" # 列出 v1 开头的标签

# 查看标签详情
git show v1.0.0

# ============================================================
# 删除标签
# ============================================================
git tag -d v0.9.0             # 删除本地标签
git push origin --delete v0.9.0  # 删除远程标签
```

## 7. 实战场景演练

### 场景1：日常开发流程

```bash
# 假设你正在开发一个博客系统

# 1. 早上开工，先拉取最新代码
git pull origin master

# 2. 创建今天的工作分支
git checkout -b feature/blog-comment master

# 3. 开始写代码...
echo "评论功能代码" > comment.py

# 4. 暂存并提交
git add .
git commit -m "feat: 添加评论功能"

# 5. 继续开发...
echo "评论回复功能" >> comment.py
git add .
git commit -m "feat: 添加评论回复功能"

# 6. 开发完成，提交 PR/MR
# 在 GitHub/GitLab 上创建 Pull Request / Merge Request

# 7. 代码合并后，切换回 master 并更新
git checkout master
git pull origin master

# 8. 删除已合并的分支
git branch -d feature/blog-comment
```

### 场景2：紧急 Bug 修复

```bash
# 正在开发新功能，突然发现生产环境有个紧急 bug

# 1. 暂存当前工作
git stash save "正在开发评论功能"

# 2. 切换到 master，创建 bugfix 分支
git checkout master
git checkout -b hotfix/urgent-bug

# 3. 修复 bug...
echo "修复代码" > fix.py
git add .
git commit -m "fix: 紧急修复XX问题"

# 4. 合并到 master 并推送
git checkout master
git merge hotfix/urgent-bug
git push origin master

# 5. 回到开发分支，继续工作
git checkout feature/blog-comment
git stash pop  # 恢复之前的进度

# 6. 删除 hotfix 分支
git branch -d hotfix/urgent-bug
```

### 场景3：撤销已推送的提交

```bash
# ⚠️ 这是"后悔药"，有风险！

# 场景：提交后发现代码有严重问题

# 方法一：revert（推荐，安全）
# 创建一个新的提交来"撤销"之前的改动
git revert commit-id

# 方法二：reset + force push（危险）
# 先回退
git reset --hard HEAD~1
# 然后强制推送到远程
git push --force origin master
# ⚠️ 注意：这会覆盖远程历史，可能影响其他人！
```

### 场景4：整理提交历史

```bash
# 场景：提交了很多零碎的 commit，想整理干净

# 1. 查看最近 5 个提交
git log --oneline -5

# 2. 变基交互式编辑
git rebase -i HEAD~5

# 3. 编辑器会打开，显示：
# pick abc1234 feat: 添加A功能
# pick def5678 feat: 修复样式问题
# pick ghi9012 feat: 添加B功能
# pick jkl3456 feat: 修复拼写错误
# pick mno7890 feat: 添加C功能

# 4. 修改成（合并相关提交，squash = 合并到上一个）：
# pick abc1234 feat: 添加A功能
# s   def5678 feat: 修复样式问题
# pick ghi9012 feat: 添加B功能
# s   jkl3456 feat: 修复拼写错误
# pick mno7890 feat: 添加C功能

# 5. 保存退出，Git 会自动合并
```

### 场景5：找回丢失的提交

```bash
# 场景：不小心 reset 硬回退了，想找回之前的提交

# 1. 查看所有操作历史
git reflog
# 输出：
# abc1234 HEAD@{0}: reset: moving to HEAD~1
# def5678 HEAD@{1}: commit: feat: 添加新功能

# 2. 找到要恢复的提交
git checkout def5678

# 3. 从这个提交创建新分支
git checkout -b recovery-branch
```

## 8. 常见问题与解决

### 问题1：撤销 git add

```bash
# 错误：不小心 add 了不想提交的文件

# 方法一：只撤销某个文件
git reset HEAD filename.txt

# 方法二：撤销所有暂存
git reset HEAD

# 方法三（新语法）：
git restore --staged filename.txt
git restore --staged .
```

### 问题2：撤销 git commit

```bash
# 错误：commit 信息写错了

# 方法一：还没 push（推荐）
git commit --amend
# 会打开编辑器，修改提交信息

# 方法二：已经 push 了
# 用 revert 创建新提交来撤销
git revert HEAD
git push origin master
```

### 问题3：撤销 git push

```bash
# 错误：push 到远程的代码有问题

# 方法一：revert（推荐，安全）
git revert HEAD
git push origin master
# 这会创建一个"撤销"的新提交

# 方法二：reset + force push（危险）
git reset --hard HEAD~1
git push --force origin master
# ⚠️ 警告：会改变远程历史，不要在协作分支使用！
```

### 问题4：处理冲突

```bash
# 冲突时 Git 会提示：
# CONFLICT (content): filename.txt

# 1. 打开冲突文件，会看到：
# <<<<<<< HEAD
# 你的代码
# =======
# 别人的代码
# >>>>>>> branch-name

# 2. 手动编辑，保留要保留的代码
# 删除 <<<<<<< ======= >>>>>>> 这些标记

# 3. 标记为已解决
git add filename.txt

# 4. 提交合并
git commit -m "merge: 解决合并冲突"
```

### 问题5：删除大文件

```bash
# 错误：提交了大文件（密码、密钥等）

# 1. 从历史记录中删除
git filter-branch --tree-filter 'rm -f password.txt' HEAD
# 或使用
git filter-repo --path password.txt --invert-paths

# 2. 垃圾回收
git gc --prune=now --aggressive

# 3. 重新添加 .gitignore
echo "password.txt" >> .gitignore
git add .gitignore
git commit -m "chore: 添加 .gitignore"

# 4. 强制推送（因为历史被改了）
git push --force origin master
```

### 问题6：忽略已提交的文件

```bash
# 文件已经在仓库中，想忽略它

# 1. 先从 Git 删除（但保留本地文件）
git rm --cached filename.txt

# 2. 添加到 .gitignore
echo "filename.txt" >> .gitignore

# 3. 提交
git add .gitignore
git commit -m "chore: 忽略敏感文件"
```
